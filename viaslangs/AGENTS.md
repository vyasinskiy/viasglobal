# Правила проекта Viaslangs

## Архитектура времен испанского языка и поле base_word_id

Для тренировки грамматических времен (например, Pretérito Indefinido и Pretérito Imperfecto) используется связанная модель карточек:
1. **Базовый инфинитив**: исходный глагол в начальной форме (например, `enviar`, `pedir`, `pagar`), у которого `base_word_id IS NULL`.
2. **Спряженные формы**: для каждого времени создаются отдельные карточки в `vy_words` для всех 6 лиц (`yo`, `tú`, `él/ella/usted`, `nosotros`, `vosotros`, `ellos/ellas/ustedes`).
3. **Связь через base_word_id**: каждая спряженная форма обязана иметь ссылку на ID своего базового инфинитива (`vy_words.base_word_id = base_verb.id`).
4. **Обязательное множественное тегирование форм**: каждая форма глагола обязана быть привязана через `vy_word_tags` минимум к 3 тегам:
   - Тег времени (например, `Pretérito Indefinido` или `Pretérito Imperfecto`).
   - Грамматический тег `Глаголы`.
   - Профильный тематический тег набора (например, `Для общения с поставщиками`).

## Логика автозачёта форм глагола (Auto-complete)

Чтобы пользователю не приходилось вводить все 6 лиц одного и того же глагола подряд во время тренировки:
1. **Правило автозачёта**: при верном ответе пользователя (`is_correct = true`) на любую форму глагола (например, 3-е лицо `envió`), бэкенд в роуте `POST /api/answers/check` автоматически добавляет правильные ответы (`is_correct = true`) для всех остальных 5 лиц этого глагола в рамках данного времени.
2. **Изоляция времен (Критично)**: автозачёт обязан затрагивать только формы того же времени. Так как формы разных времен делят общие теги `Глаголы` и `Для общения с поставщиками`, выборка обязана явно сопоставлять тег времени (`t.name IN ('Pretérito Indefinido', 'Pretérito Imperfecto')`). Формы других времен того же глагола (например, Imperfecto при ответе на Indefinido) ни в коем случае не должны засчитываться!
3. **Идемпотентность и защита от дубликатов**: запрос автозачёта содержит условие `NOT EXISTS (SELECT 1 FROM vy_answers a WHERE a.word_id = w2.id AND a.is_correct = true)`, поэтому повторный ответ на уже закрытую форму не создает дублирующих строк в базе данных.
4. **Слова без base_word_id**: если правильный ответ дан на базовый инфинитив или отдельное слово без `base_word_id`, автозачёт не запускается и другие карточки не модифицируются.
5. **Исключение из Study**: выборка неизученных слов в `/api/words/study` отфильтровывает слова через `NOT EXISTS` по правильным ответам в `vy_answers`. Поэтому после автозачёта все 6 форм глагола сразу исчезают из очереди изучения текущей сессии.

## Нечувствительность к графическим ударениям (акцентам) и регистру

При проверке ответов в `POST /api/answers/check` (в `web/app/api/answers/check/route.ts` и `server/routes/answers.ts`):
1. **Нормализация текста**: строки нормализуются через `normalizeAnswer`:
   - Приведение к нижнему регистру (`toLowerCase()`).
   - Удаление крайних пробелов и схлопывание внутренних (`trim()`, `replace(/\s+/g, ' ')`).
   - Удаление диакритических знаков ударения (`normalize('NFD').replace(/[\u0300-\u036f]/g, '')`).
2. **Равнозначность букв с ударением**: разница между `ó` и `o`, `á` и `a`, `é` и `e`, `í` и `i`, `ú` и `u` не учитывается. Ввод пользователем `acepto` для формы `aceptó` признается полностью верным ответом (`is_correct = true`) и запускает автозачёт всех связанных форм глагола.
3. **Подсказки и расстояние Левенштейна**: вычисляются по нормализованным строкам, чтобы реальные опечатки выдавали подсказку «Very close! Check your answer», а отсутствие знака ударения никогда не считалось ошибкой.

## Тестирование логики автозачёта

1. **Обязательный запуск тестов**: при любых изменениях в роутах `/api/answers/check`, `/api/words/study`, логике тегов или схеме БД агент обязан запустить интеграционные тесты:
   ```bash
   npm --prefix viaslangs/web test
   ```
2. **Тестовый набор (`viaslangs/web/tests/tenses-auto-complete.test.mjs`)**: включает 12 тестов на реальных глаголах из базы данных:
   - Базовый правильный глагол `enviar` в Indefinido.
   - Изоляция времен (формы Imperfecto остаются нетронутыми).
   - Изоляция других глаголов (`pedir`, `pagar`, `producir`).
   - Поведение при ошибке (неверный ответ не вызывает автозачёт, фиксируется 1 ошибка).
   - Глагол с чередованием e->i в Indefinido (`pedir` -> `pidió`).
   - Тренировка в Pretérito Imperfecto (`pedir` -> `pedíamos`).
   - Нерегулярный j-глагол (`producir` -> `produje`) с проверкой нечувствительности к регистру и пробелам.
   - Орфографическая замена g->gu (`pagar` -> `pagué`).
   - Идемпотентность при повторном ответе на форму.
   - Изоляция слов без `base_word_id` (базовый инфинитив `enviar`).
   - Интеграция с выборкой неизученных слов режима Study.
3. **Обязательное покрытие автотестами любых конкретных кейсов пользователя**: если пользователь указывает на конкретную проблему, краевой случай или приводит конкретный пример (например, нечувствительность к символам `ó` vs `o` на форме `acepto` -> `aceptó`), ИИ **обязан не просто скорректировать логику в коде, но и немедленно добавить отдельный тест-кейс** в `tenses-auto-complete.test.mjs`, фиксирующий именно этот пользовательский пример. Завершать задачу без добавления теста на приведенный кейс строго запрещено.
4. Завершать задачу разрешено только тогда, когда все тесты успешно проходят (`pass, fail 0`).

## Система тегов для паков слов

В приложении есть система тегов: каждый тег привязан ровно к **одному языку** (`vy_tags.language_id`), к тегу привязаны слова через связь многие-ко-многим (`vy_word_tags`). Теги нужны, чтобы группировать слова по темам (например, «Для общения с поставщиками») и включать режим повторения только слов конкретного тега.

### Правило добавления паков слов
Когда пользователь просит добавить **пак (набор) слов** в базу:

1. Если слов в паке **больше 10**, ИИ обязан:
   - Определить название тега для этого пака из контекста запроса (язык + тема). Пример: запрос «топ-50 глаголов для общения с поставщиками (испанский)» -> тег «Для общения с поставщиками» (испанский).
   - **Явно спросить пользователя и получить подтверждение названия тега** до вставки слов (через `question`/сообщение с вариантом тега).
   - После подтверждения: создать тег (с привязкой к конкретному языку), вставить слова и связать их с тегом.
2. Если пользователь просит добавить **одно слово** (или небольшой пак до 10 слов по его явной просьбе присвоить тег), ИИ обязан:
   - Почти наверняка пользователь сейчас занимается и нашёл неизвестное слово в уже существующих примерах (например, в примере «Puede contactar con nuestro gestor de pedidos por teléfono» встретилось «gestor de pedidos»). Поэтому **сначала выполнить поиск нового слова среди уже существующих слов в БД** (по лексическому совпадению, включая части фраз): если найдено похожее слово и у него уже есть тег, предложить пользователю **прикрепить новое слово к этому существующему тегу**.
   - Параллельно **проанализировать тег из контекста запроса** (язык + тема запроса пользователя).
   - **Предложить пользователю на выбор**: прикрепить к найденному/подобранному тегу(ам), либо создать новый тег, либо добавить без тега.
   - Вставить слово только после ответа пользователя; если подтверждения нет, добавить слово без тега.
3. **Обязательный анализ существующих тегов (Множественное тегирование)**:
   - Перед добавлением любой группы слов ИИ **обязан проанализировать существующие в базе теги** для целевого языка (`vy_tags`).
   - ИИ **обязан сопоставить каждое слово с потенциальными тегами**:
     - *Грамматические теги*: например, если слово является глаголом, а в базе есть тег «Глаголы», слово обязательно должно получить этот тег.
     - *Тематические теги*: если слово подходит под уже имеющиеся тематики в БД.
   - Каждое добавляемое слово должно привязываться ко **всем подходящим существующим тегам** параллельно с новым тегом пака (через таблицу связей `vy_word_tags`).
4. Если пак добавляется SQL-скриптом (seed), скрипт обязан включать: создание тега (`vy_tags`), вставку слов и заполнение связей (`vy_word_tags`) как для нового тега, так и для всех подходящих существующих тегов.
5. Утверждённое название тега фиксируется при создании и переиспользуется для того же пака при повторных добавлениях (upsert).
6. **Запрет дублирования существующих слов (Дедупликация)**:
   - Перед добавлением любого набора или отдельного слова ИИ **обязан проверить его наличие в базе данных** (`lower(english) = lower($word)` для целевого языка).
   - Если слово или выражение уже присутствует в таблице `vy_words`, **дублировать его категорически запрещено**.
   - Такое слово пропускается при вставке, а пользователю в отчете явно указывается, что слово уже есть в базе (с его ID и текущим переводом).
   - Если у найденного слова отсутствуют какие-либо из актуальных тегов (например, грамматический тег «Глаголы»), ИИ связывает его с недостающим тегом в `vy_word_tags`, не создавая дубликат слова.

## Управление и удаление карточек слов
- Удаление слова доступно прямо во время тренировки в карточке изучения (`StudyCard`):
  * Через иконку корзины («Delete word») в верхней панели карточки рядом с добавлением в избранное и редактированием.
  * Через кнопку «Delete» в левом нижнем углу модального окна редактирования слова («Edit Word»).
- При удалении запрашивается подтверждение браузера (`window.confirm`), после чего слово удаляется из БД (`DELETE /api/words/:id`), а режим изучения сразу переключается на следующее слово.
- В общем списке слов (`WordList`) удаление также доступно как в строке таблицы, так и внутри модального окна редактирования.

## Фильтрация по тегу в интерфейсе
- В шапке приложения рядом с выбором языка есть выбор тега пакета («Все слова» по умолчанию).
- При выбранном теге режим Study / Favorites и список слов фильтруются только по словам этого тега.

## Аутентификация администратора и бессрочная сессия
- **Пароль приложения**: настраивается через переменную `VIASLANGS_APP_PASSWORD` (дефолт: `viasglobal`).
- **Секрет подписи**: `VIASLANGS_APP_SECRET`.
- **Бессрочная скользящая сессия**:
  * Токен сессии подписывается HMAC-SHA256 сроком на 20 лет (`SESSION_TTL_MS`).
  * Cookie `vias_session` выставляется на 400 дней (`maxAge: 400 * 24 * 60 * 60` секунд, предел современных браузеров).
  * В `viaslangs/web/proxy.ts` реализовано автоматическое скользящее продление (sliding session): при каждом переходе по страницам cookie автоматически продлевается еще на 400 дней вперед, а старые токены обновляются. Повторный ввод пароля не требуется.

## Мобильная верстка и адаптивность (Mobile Layout)

Интерфейс веб-приложения (`viaslangs/web`) оптимизирован под экраны смартфонов и планшетов:
1. **Viewport и предотвращение зума**: в `web/app/layout.tsx` экспортируется объект `viewport` (`width: "device-width", initialScale: 1, maximumScale: 1, themeColor: "#0F172A"`), предотвращающий нежелательный авто-зум в мобильном Safari при фокусе на полях ввода.
2. **Шапка приложения (AppBar / Toolbar)**:
   - На мобильных экранах (`xs` < 600px) шапка трансформируется в двухуровневую сетку:
     * Верхняя строка: компактная иконка + название `Viaslangs` слева и кнопка выхода `Logout` справа.
     * Нижняя строка: селектор языка (`flex: 1`) и селектор пака/тега (`flex: 1.3`), равномерно делящие доступную ширину без горизонтального скролла и обрезки элементов.
   - На десктопе (`sm` и выше) элементы располагаются в одну горизонтальную строку с полным названием `VIAS - Langs learning application`.
3. **Карточка изучения (StudyCard)**:
   - На мобильных устройствах используется крупная полноразмерная кнопка «Check Answer» (высота 46px) с расположенными под ней вспомогательными действиями «Show Answer» и «Next».
   - Кнопка открытия примера («Tap to reveal») вынесена в заголовок строки примера, чтобы не накладываться на текст предложения.
   - Снекбар прогресса центрирован по горизонтали (`anchorOrigin: { vertical: 'bottom', horizontal: 'center' }`) на мобильных экранах.
4. **Список слов (WordList)**:
   - На смартфонах (`xs` и `sm`) список слов рендерится в виде карточек (`Card`) с крупным целевым словом, переводом, бейджами тегов и контекстными примерами, предотвращая горизонтальный скролл 7 колонок таблицы.
   - На десктопе (`md` и выше) отображается стандартная таблица `TableContainer` с возможностью горизонтальной прокрутки.
5. **Статистика (StatsComponent)**:
   - Кнопки быстрых действий («Today Correct» и «Clear Answers») располагаются в гибкой строке под заголовком.
   - Метрики отображаются в удобной 2-колоночной сетке на мобильных экранах и 3-колоночной на десктопе.
