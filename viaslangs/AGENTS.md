# Правила проекта Viaslangs

## Система тегов для паков слов

В приложении есть система тегов: каждый тег привязан ровно к **одному языку** (`vy_tags.language_id`), к тегу привязаны слова через связь многие-ко-многим (`vy_word_tags`). Теги нужны, чтобы группировать слова по темам (например, «Для общения с поставщиками») и включать режим повторения только слов конкретного тега.

### Правило добавления паков слов
Когда пользователь просит добавить **пак (набор) слов** в базу:

1. Если слов в паке **больше 10**, ИИ обязан:
   - Определить название тега для этого пака из контекста запроса (язык + тема). Пример: запрос «топ-50 глаголов для общения с поставщиками (испанский)» → тег «Для общения с поставщиками» (испанский).
   - **Явно спросить пользователя и получить подтверждение названия тега** до вставки слов (через `question`/сообщение с вариантом тега).
   - После подтверждения: создать тег (с привязкой к конкретному языку), вставить слова и связать их с тегом.
2. Если пользователь просит добавить **одно слово** (или небольшой пак до 10 слов по его явной просьбе присвоить тег), ИИ обязан:
   - Почти наверняка пользователь сейчас занимается и нашёл неизвестное слово в уже существующих примерах (например, в примере «Puede contactar con nuestro gestor de pedidos por teléfono» встретилось «gestor de pedidos»). Поэтому **сначала выполнить поиск нового слова среди уже существующих слов в БД** (по лексическому совпадению, включая части фраз): если найдено похожее слово и у него уже есть тег — предложить пользователю **прикрепить новое слово к этому существующему тегу**.
   - Параллельно **проанализировать тег из контекста запроса** (язык + тема запроса пользователя).
   - **Предложить пользователю на выбор**: прикрепить к найденному/подобранному тегу(ам), либо создать новый тег, либо добавить без тега.
   - Вставить слово только после ответа пользователя; если подтверждения нет — добавить слово без тега.
3. **Обязательный анализ существующих тегов (Множественное тегирование)**:
   - Перед добавлением любой группы слов ИИ **обязан проанализировать существующие в базе теги** для целевого языка (`vy_tags`).
   - ИИ **обязан сопоставить каждое слово с потенциальными тегами**:
     - *Грамматические теги*: например, если слово является глаголом, а в базе есть тег «Глаголы», слово обязательно должно получить этот тег.
     - *Тематические теги*: если слово подходит под уже имеющиеся тематики в БД.
   - Каждое добавляемое слово должно привязываться ко **всем подходящим существующим тегам** параллельно с новым тегом пака (через таблицу связей `vy_word_tags`).
4. Если пак добавляется SQL-скриптом (seed), скрипт обязан включать: создание тега (`vy_tags`), вставку слов и заполнение связей (`vy_word_tags`) как для нового тега, так и для всех подходящих существующих тегов.
5. Утверждённое название тега фиксируется при создании и переиспользуется для того же пака при повторных добавлениях (upsert).
6. **Запрет дублирования существующих слов (Дедупликация)**:
   - Перед добавлением любого набора или отдельного слова ИИ **обязан проверить его наличие в базе данных** (`lower(english) = lower($word)` для целевого языка).
   - Если слово или выражение уже присутствует в таблице `vy_words`, **дублировать его категорически запрещено**.
   - Такое слово пропускается при вставке, а пользователю в отчете явно указывается, что слово уже есть в базе (с его ID и текущим переводом).
   - Если у найденного слова отсутствуют какие-либо из актуальных тегов (например, грамматический тег «Глаголы»), ИИ связывает его с недостающим тегом в `vy_word_tags`, не создавая дубликат слова.

## Фильтрация по тегу в интерфейсе
- В шапке приложения рядом с выбором языка есть выбор тега пакета («Все слова» по умолчанию).
- При выбранном теге режим Study / Favorites и список слов фильтруются только по словам этого тега.
