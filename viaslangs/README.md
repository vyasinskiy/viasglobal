# Viaslangs - Сервис изучения и повторения языков

Веб-приложение для интервального повторения иностранных слов и профессиональной бизнес-лексики (английский и испанский языки).

---

## Архитектура и структура подпроекта

Проект разделен на три основных компонента:

- **`web/`**: современный веб-интерфейс на Next.js (App Router, Tailwind CSS, Material UI) для карточек повторения, списков слов, статистики и тегов.
- **`server/`**: REST API бэкенд на Node.js / Express и Prisma ORM, подключенный к базе данных PostgreSQL.
- **`client/`**: React SPA клиент (Vite / CRA).

### Схема базы данных (PostgreSQL)

- **`vy_languages`**: поддерживаемые языки (`code`: `en`, `es`).
- **`vy_words`**: карточки слов:
  - `english`: исходное слово / фраза на целевом языке (испанский или английский).
  - `russian`: перевод на русский язык.
  - `example_en` (`exampleEn`): контекстный пример предложения на целевом языке.
  - `example_ru` (`exampleRu`): перевод примера на русский язык.
  - `base_word_id` (`baseWordId`): ссылка на базовый инфинитив глагола для спряжённых форм времён.
  - `is_favorite`: признак избранного слова.
- **`vy_tags`**: тематические и грамматические теги (привязаны к `language_id`).
- **`vy_word_tags`**: связь слов с тегами (многие-ко-многим).
- **`vy_answers`**: история ответов и статистика правильных/неправильных попыток.

## Тематические паки слов и теги

Все слова группируются по тегам для сфокусированного изучения (например, по темам общения с поставщиками или по грамматическим категориям).

### Принцип анализа тегов и множественного тегирования:
- **Множественная привязка (M2M)**: одно слово может иметь неограниченное число тегов одновременно через таблицу `vy_word_tags`.
- **Предварительный анализ существующих тегов**: перед добавлением любого нового пакета слов выполняется автоматический анализ существующих в базе тегов для данного языка (`vy_tags`).
- **Грамматическое и тематическое тегирование**: каждое слово сопоставляется с имеющимися тегами. Например, если добавляется слово-глагол, оно обязательно привязывается к тегу «Глаголы», а также к профильному тематическому тегу своего набора.
- **Дедупликация слов (Контроль повторов)**: перед вставкой всегда выполняется проверка по `lower(english)`. Если слово уже существует в таблице `vy_words`, оно не дублируется. При необходимости к нему лишь привязываются недостающие теги.

## Спряжения времён испанского языка и автозачёт (Pretérito Indefinido / Imperfecto)

### Архитектура связи форм (`base_word_id`)
- Для 50 ключевых испанских B2B-глаголов созданы карточки спряжения во всех 6 лицах (`yo`, `tú`, `él/ella/usted`, `nosotros`, `vosotros`, `ellos/ellas/ustedes`) для двух прошедших времен: `Pretérito Indefinido` и `Pretérito Imperfecto` (всего 600 карточек).
- Каждая спряженная форма связана с базовым инфинитивом через колонку `base_word_id` (`vy_words.base_word_id = base_verb.id`). У самого инфинитива `base_word_id IS NULL`.
- Каждая карточка времени привязана минимум к 3 тегам:
  1. Тег конкретного времени (`Pretérito Indefinido` или `Pretérito Imperfecto`).
  2. Грамматический тег `Глаголы`.
  3. Профильный тематический тег пака (`Для общения с поставщиками`).

### Бизнес-логика автозачёта (Auto-complete)
При тренировке конкретного времени пользователю не требуется вводить все 6 лиц подряд:
1. При правильном ответе пользователя (`is_correct = true`) на любую форму глагола (например, 3-е лицо `envió`), бэкенд в `POST /api/answers/check` автоматически добавляет правильные ответы (`is_correct = true`) для всех остальных 5 лиц этого глагола в рамках данного времени.
2. **Изоляция времен**: выборка автозачёта явно фильтрует теги времени (`t.name IN ('Pretérito Indefinido', 'Pretérito Imperfecto')`). Формы других времен того же глагола (например, Imperfecto при ответе на Indefinido) не затрагиваются.
3. **Изоляция глаголов**: автозачёт фильтруется по `w2.base_word_id = $1`, поэтому формы других глаголов не затрагиваются.
4. **Идемпотентность**: благодаря условию `NOT EXISTS (SELECT 1 FROM vy_answers a WHERE a.word_id = w2.id AND a.is_correct = true)`, повторные ответы не приводят к дублированию записей.
5. **Исключение из Study**: режим изучения `/api/words/study` отбирает только неизученные слова (`NOT EXISTS ... is_correct = true`). Поэтому после автозачёта все 6 форм глагола в данном времени сразу исключаются из очереди изучения.

```sql
INSERT INTO vy_answers (word_id, answer, is_correct)
SELECT DISTINCT w2.id, w2.english, true
FROM vy_words w2
JOIN vy_word_tags wt2 ON wt2.word_id = w2.id
WHERE w2.base_word_id = $1
  AND w2.id != $2
  AND wt2.tag_id IN (
    SELECT t.id
    FROM vy_word_tags wt
    JOIN vy_tags t ON t.id = wt.tag_id
    WHERE wt.word_id = $2
      AND t.name IN ('Pretérito Indefinido', 'Pretérito Imperfecto')
  )
  AND NOT EXISTS (
    SELECT 1 FROM vy_answers a WHERE a.word_id = w2.id AND a.is_correct = true
  )
```

## Тестирование логики

Логика автозачёта жестко покрыта интеграционными тестами на реальных данных базы PostgreSQL.

### Запуск тестов:
```bash
npm --prefix viaslangs/web test
```

### Список тестов (`viaslangs/web/tests/tenses-auto-complete.test.mjs`):
1. **Базовый правильный глагол (`enviar`, Indefinido)**: верный ответ на 3-е лицо `envió` автоматически засчитывает все 6 форм (`envié`, `enviaste`, `envió`, `enviamos`, `enviasteis`, `enviaron`).
2. **Изоляция времён**: формы того же глагола в `Pretérito Imperfecto` (`enviaba`, `enviabas`, ...) остаются нетронутыми.
3. **Изоляция других глаголов**: формы глаголов `pedir`, `pagar` и `producir` в Indefinido не затрагиваются.
4. **Поведение при ошибке**: при неверном ответе (например, `pido` вместо `pedí`) автозачёт не срабатывает, фиксируется 1 ошибка.
5. **Глагол с чередованием e->i (`pedir`, Indefinido)**: верный ответ на форму 3-го лица `pidió` автозачитывает все 6 форм (`pedí`, `pediste`, `pidió`, `pedimos`, `pedisteis`, `pidieron`).
6. **Тренировка в Pretérito Imperfecto (`pedir`)**: ответ на форму 1-го лица мн. ч. `pedíamos` автозачитывает все 6 форм Imperfecto, не затрагивая Indefinido и другие глаголы.
7. **Нерегулярный j-глагол (`producir`, Indefinido)**: проверка нечувствительности к регистру и пробелам (`"  PRODUJE  "`), автозачёт всех 6 форм (`produje`, `produjiste`, `produjo`, `produjimos`, `produjisteis`, `produjeron`).
8. **Орфографическая замена g->gu (`pagar`, Indefinido)**: ответ на форму 1-го лица `pagué` успешно автозачитывает все 6 форм.
9. **Идемпотентность и защита от дубликатов**: повторный верный ответ на форму `pagaste` для уже закрытого глагола не создает дублирующих записей в таблице ответов.
10. **Обычные слова без `base_word_id`**: верный ответ на базовый инфинитив `enviar` не запускает автозачёт других слов.
11. **Интеграция с режимом Study**: эндпоинт `/api/words/study` сразу исключает все 6 автозачтенных форм глагола из списка неизученных слов.

## Сид-скрипты в `server/prisma/`:
- **`seed-es-verbs.sql`**: топ-50 ключевых испанских глаголов для B2B общения с поставщиками.
- **`seed-tag-supplier-communication.sql`**: создание тега «Для общения с поставщиками» и привязка к нему базовых глаголов.
- **`seed-es-supplier-phrases.sql`**: 13 устойчивых выражений и терминов B2B-переписки.
- **`seed-tag-verbs.sql`**: создание тега «Глаголы» и привязка к нему всех 50 испанских глаголов для отдельного повторения.
- **`seed-es-tenses.sql`**: создание тегов `Pretérito Indefinido` и `Pretérito Imperfecto`, добавление 600 форм спряжения для 50 глаголов с B2B-примерами и привязкой `base_word_id`.

## Запуск проекта

### Локальная разработка

```bash
# Установка зависимостей
npm run install:all

# Запуск бэкенда и фронтенда параллельно
npm run dev
```

### Применение SQL-сидов

Для загрузки подготовленных паков слов в базу данных:

```bash
psql -h localhost -U <user> -d <database> -f server/prisma/seed-es-supplier-phrases.sql
```
