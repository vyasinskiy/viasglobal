# Данные Keepa и интеграция с Keepa Product Finder API

В этой директории хранятся выгрузки (в форматах Excel, CSV и т.д.) из сервиса Keepa, а также документация по интеграции с Keepa API для оптового реселлинга (Wholesale) на платформе Amazon Europe (домен `amazon.es`).

---

## 1. Конфигурация Keepa Product Finder API

Для автоматического поиска оптовых товаров используется официальный эндпоинт Keepa API:
- **URL**: `POST https://api.keepa.com/query?key={KEY}&domain=4`
- **Домен**: 4 (`amazon.es`, Испания).

### Утвержденный шаблон запроса

```json
{
  "productType": [0],
  "current_SALES_gte": 1,
  "current_SALES_lte": 50000,
  "current_BUY_BOX_SHIPPING_gte": 1500,
  "current_BUY_BOX_SHIPPING_lte": 10000,
  "current_COUNT_NEW_gte": 5,
  "current_COUNT_NEW_lte": 15,
  "rootCategory": ["599391031"],
  "isAdultProduct": false,
  "sort": [
    ["current_SALES", "asc"],
    ["monthlySold", "desc"]
  ],
  "perPage": 100,
  "page": 0
}
```

### Детальное обоснование каждого поля фильтра

1. **`productType: [0]` (Тип продукта)**:
   - Значение: физические товары Amazon (Physical Products).
   - Обоснование: отсекает цифровой контент, приложения, подписки, электронные книги Kindle и аудиокниги Audible (типы 1, 2, 3), оставляя только реальные материальные товары, подходящие для оптовой перепродажи со склада FBA.
2. **`current_SALES_gte: 1` и `current_SALES_lte: 50000` (Диапазон Sales Rank / BSR)**:
   - `gte: 1`: позволяет захватить высоколиквидные бестселлеры. Быстрая распродажа и высокая скорость оборота средств (Cash Velocity) высвобождают капитал для новых закупок.
   - `lte: 50000`: исключает «мертвый хвост» низколиквидных товаров со слабым спросом, которые рискуют зависнуть на складах FBA и генерировать растущую плату за хранение (Aged inventory surcharge).
3. **`current_BUY_BOX_SHIPPING_gte: 1500` и `current_BUY_BOX_SHIPPING_lte: 10000` (Цена Buy Box с доставкой)**:
   - Значения указаны в евроцентах (от 15.00 € до 100.00 €).
   - `gte: 1500 (15.00 €)`: защитный барьер маржинальности. На товарах дешевле 15 € фиксированные сборы Amazon (сборка и упаковка FBA Pick & Pack ~3.5-5 €, 15% комиссия маркетплейса и НДС/IVA) съедают большую часть выручки, делая оптовую перепродажу нерентабельной.
   - `lte: 10000 (100.00 €)`: защита оборотного капитала. Закупка дорогих позиций требует крупных единовременных инвестиций, а возвраты или повреждения наносят ощутимый урон начинающему продавцу.
4. **`current_COUNT_NEW_gte: 5` и `current_COUNT_NEW_lte: 15` (Количество продавцов нового товара)**:
   - `gte: 5`: гарантия оптовой доступности бренда и защита от жалоб на нарушение авторских прав (IP Complaints). Если листинг делят 5 и более продавцов, бренд лоялен к сторонним реселлерам и не блокирует продажи через юристов (в отличие от Private Label с 1 продавцом).
   - `lte: 15`: защита от бесконтрольного демпинга цен. Листинги с 20-30 продавцами страдают от ценовых войн автоматических репрайсеров, снижающих цену ниже себестоимости.
5. **`rootCategory` (Корневая категория)**:
   - Динамический массив с идентификатором категории (Browse Node ID). Опрос ведется строго по одной категории за раз из утвержденного белого списка, чтобы не перегружать токены API и поддерживать чистоту выборки.
6. **`sort` (Сортировка)**:
   - Двухуровневая сортировка: в первую очередь товары с лучшим текущим рангом продаж (`current_SALES: asc`), во вторую очередь по объему ежемесячных продаж (`monthlySold: desc`).
7. **`perPage: 100` и `page: 0` (Пагинация)**:
   - Стандартный размер страницы выдачи (100 ASIN), позволяющий экономно расходовать токены Keepa.

## 2. Специальный анализ: Почему товары 18+ строго исключены (`isAdultProduct: false`)

Для реселлера в статусе индивидуального предпринимателя в Испании (**autónomo**) работа с категорией Adult несет критические риски:

1. **Неограниченная ответственность личным имуществом (ст. 1911 Гражданского кодекса Испании)**:
   - По закону автоном отвечает по обязательствам всем своим настоящим и будущим имуществом (квартира, дом, счета, автомобиль).
   - Товары для взрослых (лубриканты, смазки, средства гигиены) имеют прямой контакт со слизистыми оболочками. В случае аллергического шока, химического ожога или инфекции покупатель подает иск на компенсацию вреда здоровью продавцу. В отличие от юрлица (SL), у автонома нет щита ограниченной ответственности.
2. **100% потеря средств при возвратах (Без права перепродажи)**:
   - По санитарным регламентам Евросоюза товары интимного назначения после возврата покупателем категорически запрещено возвращать на склад для повторной продажи. Amazon сразу маркирует их как `Customer Damaged` и принудительно списывает на утилизацию за счет продавца.
3. **Теневой бан алгоритмов Amazon (De-indexing)**:
   - Карточки с флагом Adult удаляются из стандартного сквозного поиска Amazon и исключаются из всех рекомендательных блоков («С этим товаром также покупают», «Похожие товары»).
4. **Полный запрет на платную рекламу (No Amazon Ads)**:
   - Правила Amazon Advertising полностью запрещают запуск PPC рекламы (Sponsored Products) для товаров категории Adult.
5. **Складские штрафы за упаковку FBA (Inbound Defect)**:
   - Amazon требует специальную непрозрачную черную упаковку (Blackout packaging). Поставка в стандартной прозрачной пленке приводит к штрафам и блокировке поставок.

## 4. Использование API и CLI-скриптов

### Запуск через консольный скрипт:
```bash
# Просмотр списка активных категорий из БД:
npx tsx scripts/fetch-keepa-product-finder.ts --list

# Запуск поиска по конкретной категории (например, Дом и кухня):
npx tsx scripts/fetch-keepa-product-finder.ts 599391031

# Запуск поиска по всем активным категориям из БД по очереди:
npx tsx scripts/fetch-keepa-product-finder.ts --all
```

### Запуск через HTTP API бэкенда:
- `GET /keepa/allowed-categories`: список разрешенных категорий из базы данных.
- `POST /keepa/product-finder/category/:categoryId`: запуск поиска по конкретной категории.
- `POST /keepa/product-finder/all`: последовательный запуск поиска по всем активным категориям.

Все найденные ASIN автоматически помещаются в таблицу `WholesaleAsinQueue` с приоритетом `10` для последующего сбора подробных данных через фоновый сервис `KeepaService`.
