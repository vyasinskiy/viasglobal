## 2. Соглашения по форматированию интерфейса Telegram
- **Сумма и статус начислений**: Запрещено выводить сырые технические строки разметки из БД (например, `initialBalance=...`). Вместо этого парсите поле `item.rawJson` в сервисе бота, выводя чистое отформатированное значение суммы (например, `1048.33 руб.`) и человекочитаемые русские статусы (например, `Оплачено`, `Ожидает оплаты`).

## 3. Правила написания кода и типизации
- **Запрет на использование `any`**: Использование типа `any` в TypeScript коде строго запрещено. Вместо этого используйте строгие типы, интерфейсы или тип `unknown` с последующим сужением типов (type guarding).

- **Запрет на использование Bootstrap-классов и `sx`**: В проекте запрещено использовать классы из Bootstrap и проп `sx` (например, из MUI). Стили должны быть определены в файлах CSS, подключаемых через `globals.css` или модули. Это обеспечивает единообразие и премиальный дизайн без внешних CSS‑фреймворков.
- **Разрешено использовать модульные стили (CSS Modules)**: Для стилизации компонентов используйте файлы `*.module.css`. Классы импортируются как объект стилей и применяются через `className={styles.className}`. Это гарантирует изоляцию CSS и предотвращает конфликты.
- **Разрешено использовать библиотеку MUI (`@mui/material`) для компонентов**: Компоненты могут быть импортированы и использованы, однако их стилизация должна происходить через CSS‑классы или `styled`‑компоненты, а не через проп `sx`.

## 4. Архитектурные ограничения взаимодействия
- **Запрет на прямое подключение к БД из Admin UI**: Панель администратора (`admin-ui`) не должна подключаться напрямую к базе данных (PostgreSQL) и использовать Prisma-клиент. Все операции чтения данных и изменения состояний должны осуществляться через запросы к REST API соответствующих микросервисов (в частности, микросервиса `accountant`). Это сохраняет изоляцию сервисов и централизует бизнес-логику.

## 5. Финансовый AI-ассистент учета платежей (DeepSeek-V3 + Whisper)
- **Роль и назначение**: Анализ входящих сообщений владельца недвижимости (транскрибированный голос, свободный текст, чеки/квитанции), сопоставление со справочником квартир и арендаторов (`Tenant`, `Apartment`, `Invoice`) и подготовка структурированного платежа. Шаблон промпта хранится в [промт.md](file:///Users/usuario/code/viasglobal/rent/%D0%BF%D1%80%D0%BE%D0%BC%D1%82.md).
- **Схема и классификация**:
  * Статусы: `ready` (определен однозначно) или `needs_clarification` (неоднозначность жильца/суммы).
  * Типы платежей: `RENT`, `UTILITIES`, `COMBINED` (с детализацией `subPayments`), `DEPOSIT`, `OTHER`.
  * Банки: нормализация названий (`Сбербанк`, `Т-Банк`, `Альфа-Банк`, `ВТБ`, `Не указан`).
- **Человеческий контроль (Human-in-the-loop)**: AI формирует исключительно проект (черновик) платежа с инлайн-кнопками подтверждения в Telegram. Запись в базу данных через микросервис `accountant` (`create_payment` со статусом `confirmed`) выполняется строго после явного клика администратора по кнопке «Подтвердить».
