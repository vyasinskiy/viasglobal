## 2. Соглашения по форматированию интерфейса Telegram
- **Сумма и статус начислений**: Запрещено выводить сырые технические строки разметки из БД (например, `initialBalance=...`). Вместо этого парсите поле `item.rawJson` в сервисе бота, выводя чистое отформатированное значение суммы (например, `1048.33 руб.`) и человекочитаемые русские статусы (например, `Оплачено`, `Ожидает оплаты`).

## 3. Правила написания кода и типизации
- **Запрет на использование `any`**: Использование типа `any` в TypeScript коде строго запрещено. Вместо этого используйте строгие типы, интерфейсы или тип `unknown` с последующим сужением типов (type guarding).

- **Запрет на использование Bootstrap-классов и `sx`**: В проекте запрещено использовать классы из Bootstrap и проп `sx` (например, из MUI). Стили должны быть определены в файлах CSS, подключаемых через `globals.css` или модули. Это обеспечивает единообразие и премиальный дизайн без внешних CSS‑фреймворков.
- **Разрешено использовать модульные стили (CSS Modules)**: Для стилизации компонентов используйте файлы `*.module.css`. Классы импортируются как объект стилей и применяются через `className={styles.className}`. Это гарантирует изоляцию CSS и предотвращает конфликты.
- **Разрешено использовать библиотеку MUI (`@mui/material`) для компонентов**: Компоненты могут быть импортированы и использованы, однако их стилизация должна происходить через CSS‑классы или `styled`‑компоненты, а не через проп `sx`.

## 4. Архитектурные ограничения взаимодействия
- **Запрет на прямое подключение к БД из Admin UI**: Панель администратора (`admin-ui`) не должна подключаться напрямую к базе данных (PostgreSQL) и использовать Prisma-клиент. Все операции чтения данных и изменения состояний должны осуществляться через запросы к REST API соответствующих микросервисов (в частности, микросервиса `accountant`). Это сохраняет изоляцию сервисов и централизует бизнес-логику.

## 5. Финансовый AI-ассистент учета платежей (DeepSeek-V3 + Whisper)
- **Роль и назначение**: Анализ входящих сообщений владельца недвижимости (транскрибированный голос, свободный текст, чеки/квитанции), сопоставление со справочником квартир и арендаторов (`Tenant`, `Apartment`, `Invoice`) и подготовка структурированного платежа. Шаблон промпта хранится в [промт.md](file:///Users/usuario/code/viasglobal/rent/%D0%BF%D1%80%D0%BE%D0%BC%D1%82.md).
- **Схема и классификация**:
  * Статусы: `ready` (определен однозначно) или `needs_clarification` (неоднозначность жильца/суммы).
  * Типы платежей: `RENT`, `UTILITIES`, `COMBINED` (с детализацией `subPayments`), `DEPOSIT`, `OTHER`.
  * Банки: нормализация названий (`Сбербанк`, `Т-Банк`, `Альфа-Банк`, `ВТБ`, `Не указан`).
- **Человеческий контроль (Human-in-the-loop)**: AI формирует исключительно проект (черновик) платежа с инлайн-кнопками подтверждения в Telegram. Запись в базу данных через микросервис `accountant` (`create_payment` со статусом `confirmed`) выполняется строго после явного клика администратора по кнопке «Подтвердить».

## 7. Детекция сессии и парсинг квитанций (Watcher Service)
- **Рабочие домены портала**: 
  * Публичная авторизация: `https://квартплата.онлайн/login` (`https://xn--80aaaf3bi1ahsd.xn--80asehdb/login`).
  * Авторизованный личный кабинет жителя и внутренний API (`/new-web/apartments`): `https://лк.квартплата.онлайн/` (`https://xn--j1ab.xn--80aaaf3bi1ahsd.xn--80asehdb/`).
  * Старый домен `new-лк...` (`xn--new--o5df...`) более не используется, так как возвращает 302 редирект на главную.
- **Защита от сброса сессии и ложноположительных срабатываний**: Функция `checkIsLoginRequired` проверяет наличие признаков кабинета (хост `xn--j1ab`, пути с ID Л/С, ключевые слова меню `'счётчики'`, `'платежи'`, `'заявки'`, `'магазин'`, `'выйти'`). Профиль Chromium в контейнере автоматически настраивается с параметром `restore_on_startup: 1`, что предотвращает удаление session cookies при закрытии браузера. При успешном сканировании сессия дополнительно сохраняется в `data/storage-state.json`.
- **Статус `needs_login`**: При `needsLogin === true` сервис обязан передавать статус `needs_login` в RabbitMQ (`scan_completed`), чтобы Telegram-бот отправлял администраторам сообщение с эмодзи 🔑 и текстом `Требуется авторизация`.
- **Обновление сессии в 1 клик**: При статусе `needs_login` бот или сервис автоматически стартуют контейнер удаленного браузера `accruals-visual-browser` через эндпоинт `POST /scraping/browser/start` (или сообщение `start_browser`). В Telegram администратору отправляется сообщение с кнопкой-ссылкой `🌐 Открыть браузер` (`https://browser.viasglobal.es`) и инлайн-кнопкой `✅ Я вошел в кабинет`. Владелец переходит по ссылке, входит по SMS в удаленном окне Chromium, возвращается в Telegram и нажимает кнопку подтверждения. Бот автоматически останавливает браузер через `POST /scraping/browser/stop` (снимая блокировку профиля и фиксируя сессию) и сразу проводит контрольное сканирование начислений. Также доступна команда `/browser` и кнопка `🔑 Браузер ЖКХ` в главном меню бота.

## 8. Управление через ИИ-агентов по HTTP и полнота ответов для диагностики
- **Управление по HTTP**: Сервисы `accountant`, `watcher`, `admin-ui` и `telegram-bot` поддерживают управление и мониторинг автономными AI-ассистентами (OpenClaw, Hermes, Antigravity) через внутренние REST эндпоинты по Docker-сети `infra_accruals-network`.
- **Полнота ответов для диагностики**:
  * Все эндпоинты запуска процессов (например, `POST /scraping/scan`, операции `accountant`) обязаны возвращать структурированный ответ со статусом (`status: 'success' | 'warning' | 'needs_login' | 'error'`), текстовым сообщением `message`, явным полем `error` и массивом `errors`.
  * Категорически запрещено возвращать неинформативные или пустые ответы при возникновении сбоев.
  * Все проблемные запуски обязаны сохраняться в базу данных (`runs`), чтобы их статус и причина ошибки отображались в веб-панели и журнале аудита.

## 9. Локальное хранилище квитанций (Local Storage)
- **Автономный режим**: Хранение PDF-файлов квитанций осуществляется локально на диске сервера без внешней зависимости от AWS S3 (`S3_ENABLED=false`).
- **Персистентность данных**: Папка `data/uploads/` сервиса `accountant` монтируется через Docker volume `${ACCOUNTANT_PATH}/data:/app/data`.
- **Протокол загрузки**: Воркер `watcher` запрашивает URL для загрузки через `GET /accountant/invoices/upload-url`, `accountant` возвращает `PUT /accountant/invoices/upload-raw?key=...`. Воркер передает бинарный поток PDF файла, и `accountant` сохраняет его в `data/uploads/`.
- **Скачивание и выдача**:
  * Скачивание файла: `GET /accountant/invoices/download/:key`.
  * Telegram-бот: скачивает бинарный буфер по внутренней сети Docker из `accountant` и отправляет файл в чат как документ `{ source: buffer, filename }`.
  * Admin UI: API-роут `/api/invoices/[id]/download` проксирует поток PDF файла напрямую в браузер пользователя.
