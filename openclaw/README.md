# Персональный AI-ассистент на платформе OpenClaw

Автономный сервис личного ассистента на базе платформы **OpenClaw**, запущенный в Docker-контейнере параллельно с сервисом `hermes`.

## Возможности

1. **Мультиканальный шлюз OpenClaw**:
   - Работает через выделенного Telegram-бота для владельца (`allowFrom: [743866013]`).
   - Поддерживает расширения, сессии, долговременную память и автоматизацию.

2. **Модель и модульные пресеты**:
   - Поддерживает модульные пресеты моделей с индивидуальными лимитами контекста и стратегиями кэширования: `gpt-6-luna`, `claude-haiku-5.5`, `mimo-v2.6-flash`, `deepseek-chat`.
   - Полное сравнение, анализ стоимости кэша и обоснование параметров вынесены в [MODELS.md](file:///Users/usuario/code/viasglobal/openclaw/MODELS.md).
   - По умолчанию используется **OpenAI GPT-6 Luna** (`openai/gpt-6-luna`) с лимитом `contextTokens: 128000` для предотвращения переплат за кэш. Переключение модели выполняется через переменную `MODEL` в `.env`.

3. **Сетевая интеграция и реестр микросервисов**:
   - Прямой доступ к сервису аренды (`accruals-accountant:3005`).
   - Прямой доступ к сервису оптовой торговли (`backend:3000`).
   - Прямой доступ к парсеру ЖКХ (`accruals-watcher:4500`).
   - Автоматическая синхронизация реестра микросервисов из `docs/SERVICES.md` в рабочую область агента `data/workspace/SERVICES.md` при каждом развертывании.

4. **Режим экономии токенов и контроль контекста**:
   - **Отключение Heartbeat**: фоновый опрос (`heartbeat.every: "0m"`) отключен. Агент не тратит токены вхолостую и не отправляет ложные сообщения `NO_REPLY` в чат. Он активируется строго при входящих обращениях пользователя.
   - **Ограничение активного окна (`contextTokens`)**: в конфигурации нативно задан лимит активного контекста под конкретную модель (128k для Luna, 48k для Haiku, 128k для MiMo).
   - **Авто-компактификация (`compaction`)**: режим `safeguard`, порог размера транскрипта `maxActiveTranscriptBytes: "3mb"`, сохранение последних 3 реплик `recentTurnsPreserve: 3`, а также `midTurnPrecheck` для предотвращения переполнения контекста внутри циклов вызова инструментов.
   - **Очистка вызовов инструментов (`contextPruning`)**: режим `cache-ttl` (TTL 5 минут), автоматически удаляющий объемные выгрузки сырых JSON/вызовов curl из контекста после завершения шага.
   - **Сброс сессии**: пользователю рекомендуется сбрасывать контекст диалога командой `/new` или `/reset` в Telegram после завершения задачи.

5. **Защита от галлюцинаций (Anti-Hallucination & Bad Request)**:
   - Агент строго соблюдает регламент единого источника правды (`SERVICES.md`).
   - Запрещено использовать плейсхолдеры (`***`, `...`, `<id>`).
   - Ответ `400 Bad Request` от сервисов интерпретируется как необходимость скорректировать параметры запроса, а не как сбой сервера. Запрещены любые деструктивные обходные пути.

6. **Интеллектуальный учет ретроспективных платежей**:
   - При регистрации платежей по чекам или скриншотам агент учитывает возможность создания платежа с временной задержкой относительно дня реальной оплаты.
   - Агент анализирует дату квитанции, чека СБП, банкомата или дату сообщений на скриншотах, передает ее в поле `paymentDate` (ISO 8601), определяет обслуживающий банк (`bankId`) и обязательно фиксирует обоснование причины определения даты в проекте и комментарии к платежу.

7. **Прозрачный мониторинг расходов и размера контекста**:
   - Бот автоматически прикрепляет информационный футер в конце каждого ответа в Telegram (`messages.responseUsage: "full"`).
   - В футере отображаются: активная модель, размер занятого контекста относительно безопасного окна модели (например, `📊 Контекст: 12k/128k (9%)`), точная стоимость текущего запроса по тарифам OpenRouter (`💰 Запрос: $0.0004`) и количество затраченных токенов (`⚡ 850 tok`).
   - Управление футером в Telegram: `/usage reset` (вернуть полный футер по умолчанию) и `/usage cost` (сводный отчет по расходам).

## Структура подпроекта

```text
viasglobal/openclaw/
├── .agents/
│   └── AGENTS.md                   # Правила для ИИ ассистента
├── README.md                       # Данный документ
├── MODELS.md                       # Паспорт и реестр пресетов LLM моделей
├── Makefile                        # Команды управления (make deploy, make logs)
├── deploy.sh                       # Скрипт сборки конфигурации и запуска
├── docker-compose.yml              # Описание контейнера viasglobal-openclaw
├── .env.example                    # Шаблон переменных окружения
├── .env                            # Файл с API-ключами (не коммитится)
├── config/
│   ├── openclaw.template.json      # Базовый шаблон конфигурации OpenClaw
│   ├── build-config.py             # Скрипт сборки конфига с пресетом модели
│   ├── models/                     # Каталог модульных пресетов моделей
│   │   ├── gpt-6-luna.json         # Пресет OpenAI GPT-6 Luna (contextTokens: 128k)
│   │   ├── claude-haiku-5.5.json   # Пресет Anthropic Claude Haiku (contextTokens: 48k)
│   │   ├── mimo-v2.6-flash.json    # Пресет Xiaomi MiMo Flash (contextTokens: 128k)
│   │   └── deepseek-chat.json      # Пресет DeepSeek V3 (contextTokens: 64k)
│   └── workspace/
│       └── AGENTS.md               # Базовые инструкции для workspace OpenClaw
└── data/                           # Смонтированный том данных (~/.openclaw)
    └── workspace/
        ├── SERVICES.md             # Автосинхронизированный реестр API сервисов
        └── AGENTS.md               # Инструкции агента по вызовам API
```

## Развертывание и обновление

> **Важно**: при любом изменении `docs/SERVICES.md` всегда запускайте `make redeploy-openclaw`, чтобы актуализировать файл `SERVICES.md` в контейнере агента.

### 1. Из корня репозитория:
- Полное развертывание: `make deploy-openclaw`
- Быстрое обновление реестра сервисов и кода: `make redeploy-openclaw`

### 2. Прямо на сервере Huawei:
```bash
cd ~/viasglobal/openclaw
make deploy
```
