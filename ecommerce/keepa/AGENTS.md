# Инструкции для ИИ (Keepa)

*Правила для ИИ:*
1. **Поиск исходных данных**: При запросах на обработку таблиц с товарами или поиске дистрибьюторов по ASIN, по умолчанию ищи исходные данные (Excel/CSV файлы) в этой директории. Для автоматизированного поиска B2B дистрибьюторов в Европе используй специально настроенный навык (skill) `find-distributor`.
2. **Работа с Keepa Product Finder API**:
   - При формировании запросов к эндпоинту `/query` Keepa API всегда используй утвержденный безопасный JSON-шаблон.
   - Категории выбираются строго динамически из таблицы базы данных `KeepaAllowedCategory` (белый список безопасных категорий).
   - Никогда не делай единый запрос без указания категории (`rootCategory`). Опрос выполняется строго по одной категории за раз с паузами между запросами не менее 2 секунд для экономии лимита токенов API.
3. **Строгий запрет на товары 18+ (Adult Products)**:
   - В любых запросах поиска товаров для оптового реселлинга параметр `isAdultProduct` обязан иметь значение `false`.
   - Продавец работает в юридическом статусе autónomo (неограниченная личная ответственность по ст. 1911 ГК Испании). Товары категории Adult несут высокий риск претензий по вреду здоровью, теневой бан в поиске, запрет рекламы и 100% невозвратные списания при возвратах.
4. **Контроль очереди ASIN**:
   - Все найденные через Product Finder идентификаторы ASIN обязаны добавляться в таблицу `WholesaleAsinQueue` методом `upsert` с базовым приоритетом (10), чтобы избежать дублирования и повторного расхода токенов.
   - Детальные характеристики товаров собираются фоновым сборщиком `KeepaService.fetchRawData()` с кэшированием на 14 дней.
5. **Запрет длинного тире (`—`)**:
   - В любых генерируемых отчетах, комментариях и текстах запрещено использовать длинное тире `—` и среднее тире `–`. Использовать только стандартный дефис `-` или естественную пунктуацию.
6. **Правило подозрительного равенства размера выборки лимиту пагинации (Анти-срез каталога)**:
   - Если итоговое число выгруженных товаров/ASIN ровно равно лимиту фильтра (например, ровно **100** при дефолтной настройке пагинации Keepa или ровно **5000** при максимальном лимите одной страницы), это считается крайне подозрительным и указывает на техническую ошибку или срез пагинации вместо полного каталога.
   - ИИ обязан бить тревогу и перепроверять процесс:
     * При ровно 100 товарах: перепроверить переключение меню строк `.tool__row` на 5000 rows в Playwright и повторить выгрузку.
     * При ровно 5000 товарах: уведомить пользователя о превышении лимита страницы и запустить сегментацию по диапазонам Sales Rank (BSR).
