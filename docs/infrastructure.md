# Архитектура кластера Viasglobal (Peer-to-Peer)

В данном проекте используется децентрализованная (Peer-to-Peer) архитектура на базе **Tailscale** и **Docker**. Это позволяет отказаться от платных облачных серверов, сохраняя при этом безопасность и удобство масштабирования.

## Как это работает?

### 1. Tailscale (VPN Overlay)
Все устройства (Домашний ПК и Mac) объединены в защищенную частную сеть с помощью Tailscale (основан на WireGuard).
- Tailscale пробивает NAT-роутеры без необходимости настраивать проброс портов (Port Forwarding).
- Каждое устройство получает **статический внутренний IP-адрес** (например, `100.92.50.18`), который никогда не меняется.
- Доступ к базам данных и сервисам происходит только по этим внутренним IP, что исключает доступ из открытого интернета.

### 2. Беспарольный SSH (Tailscale SSH)
Tailscale предоставляет встроенную функцию `Tailscale SSH`, которая управляет доступом на основе аккаунта Google/GitHub.
- Включение: `sudo tailscale up --ssh`
- Подключение с Мака: `ssh huawei@100.92.50.18`
Вам не нужно генерировать и копировать RSA ключи — Tailscale пускает вас автоматически, так как оба устройства авторизованы в одном аккаунте.

### 3. Удаленный деплой (Docker Context over SSH)
Мы не используем тяжеловесные оркестраторы вроде Docker Swarm или Kubernetes. Вместо этого используется нативная возможность Docker CLI работать по SSH.

Установив переменную `DOCKER_HOST`, вы приказываете локальному клиенту Docker на Маке передать команды демону Docker на домашнем ПК:
```bash
DOCKER_HOST=ssh://huawei@100.92.50.18 docker compose -f docker-compose.primary.yml up -d
```
Это позволяет управлять сервером "с дивана", не подключаясь к нему явно.

## Топология кластера

### Узел 1: Primary (Домашний ПК Huawei MateStation S - Linux)
**IP:** `100.92.50.18`

*   **Базы данных (Master):** 2 изолированные СУБД:
    * `backend-db-1` (Postgres 15, порт `5432`) — `viasglobal_db` (Wholesale каталог, 100k+ ASIN, закупки, остатки СВХ/склада, продажи).
    * `accruals-postgres` (Postgres 16, порт `5433`) — сервис аренды (`accountant_db`, `watcher_db`, `telegram_bot_db`, `kvartplata_watcher`).
*   **Микросервисы и веб-интерфейсы:**
    * `backend-backend-1` (порт `3001`) — API Wholesale каталога, заказов и остатков.
    * `accruals-admin-ui` (порт `3000`) — веб-панель аренды (`rent.viasglobal.es`).
    * `accruals-accountant` (порт `3005`), `accruals-watcher` (порт `4500`), `accruals-rabbitmq` (порты `5672`, `15672`).
    * `sms-gateway` (порт `3040`), `viasglobal-openclaw` (порт `18789`), `viasglobal-hermes`.
*   **Внешний доступ (Cloudflare Tunnel):** Контейнер `cloudflared` (токен туннеля `fad800a3-f97e-4b41-8f24-df8168b1211b`).

### Узел 2: Standby / Disaster Recovery (Mac)
**IP:** `100.65.210.51`

*   **Резервная среда мгновенного развертывания (Disaster Recovery):** Все Docker-образы (`backend`, `rent`, `cloudflared`) предсобраны и закэшированы локально.
*   **Синхронизация бэкапов:** Ежедневно через `make backup-sync` свежие копии всех БД скачиваются в `backend/backups/`.
*   **Аварийное переключение в 1 команду:** При выходе Huawei из строя команда `make dr-failover` за 2 минуты разворачивает все СУБД, восстанавливает данные и запускает локальный `cloudflared-failover`. Трафик внешних сайтов переключается на Mac без изменения DNS.
*   **Возврат работы на Huawei:** Команда `make dr-rollback`.

## 4. Публикация веб-интерфейсов через Cloudflare Tunnel

Для безопасного внешнего доступа к веб-интерфейсам кластера (без открытия портов на роутере и без белого статического IP) используется **Cloudflare Tunnel** (`cloudflared`).

### Конфигурация туннеля:
- **Туннель**: `fad800a3-f97e-4b41-8f24-df8168b1211b` (аккаунт `ac8ad485b5af13d1cfdf0e7b1adfdb12`).
- **Сетевое окружение**: Контейнер подключен к Docker-сети `infra_accruals-network`.
- **Маршрутизация поддоменов Cloudflare**:
  - `rent.viasglobal.es` -> `http://100.92.50.18:3000` (панель управления учетом аренды и начислений).
  - `browser.viasglobal.es` -> `http://100.92.50.18:3002` (удаленный визуальный браузер для SMS-авторизаций).
  - `portainer.viasglobal.es` -> `http://100.92.50.18:9000` (панель управления Docker контейнерами).
