# Инструкция для ИИ

## Задача
Пользователь передает тебе список брендов и соответствующих им ASIN (обычно это результат работы навыка `filter-asins`).
Твоя цель — найти контакты официальных европейских B2B дистрибьюторов (wholesale) для указанных брендов.

## Алгоритм работы (Фаза 1: Подготовка промпта)
1. **Делегирование поиска**: Тебе запрещено самостоятельно искать контакты дистрибьюторов в интернете. Эта работа делегируется аналитической нейросети пользователя. 
   - (Проверка в БД на статус "Приватный лейбл" уже должна быть выполнена на предыдущем этапе фильтрации. Приватные лейблы отсекаются, а остальные бренды берутся в работу).
2. **Генерация промптов для анализа**:
   - Для каждого переданного бренда/производителя прочитай файл-шаблон `other/distributor_screening/prompt.md`.
   - Замени в тексте шаблона плейсхолдер `[ВСТАВЬТЕ НАЗВАНИЕ ИЛИ САЙТ ДИСТРИБЬЮТОРА]` на название переданного бренда или производителя.
   - Создай папку для данного дистрибьютора по пути `other/distributor_screening/<название_бренда>/`.
   - Сохрани готовый промпт в файл `other/distributor_screening/<название_бренда>/prompt.md` и ОБЯЗАТЕЛЬНО попроси пользователя прогнать этот промпт через NotebookLM (или Perplexity) и прислать тебе полученный отчет в чат. Ожидай ответа пользователя перед переходом к Фазе 2.

## Фаза 2: Валидация отчета NotebookLM (Сверка "Де-юре" и "Де-факто")
Получив от пользователя готовый отчет из NotebookLM по дистрибьютору, ты не должен слепо верить его выводам о "Высоком риске". Поисковые ИИ часто читают юридические формулировки слишком буквально (так как производители перестраховываются перед правообладателями лицензий).

Твоя задача — сопоставить теоретический отчет с реальной ситуацией из нашей базы данных:
1. **Сбор фактов из БД (Де-факто)**: 
   - Напиши временный скрипт на TypeScript (с использованием `PrismaClient` в папке `backend`) для выборки данных по этому производителю или бренду из функции `get_wholesale_candidates()` или представления `WholesaleCandidatesView`.
   - Проанализируй: сколько ASIN активно продается (где `filterReason` = null)? Каково разнообразие продавцов в BuyBox?
   - Изучи названия продавцов (`sellerName`). Это транснациональные корпорации или обычные локальные магазинчики?
2. **Анализ расхождений**:
   - Если ИИ пишет "Строгий запрет на онлайн-продажи / Селективная дистрибуция", а в БД десятки активных мелких селлеров на Amazon, сделай вывод, что де-факто фабрика лояльна к оптовикам, которые обеспечивают сбыт (при условии соблюдения РРЦ и наличия официальных фактур).
3. **Финальный сводный отчет**:
   - Скорректируй уровень риска на основе эмпирических данных из БД.
   - Выдели из отчета NotebookLM самую ценную практическую информацию: точные реквизиты юрлиц (чтобы не перепутать S.A. с S.L.), найденных суб-дистрибьюторов (например, B2B-порталы с низким MOQ), точные пороги бесплатной доставки.
   - Дай окончательную рекомендацию по стратегии: как позиционировать нашу компанию при контакте (опираясь на Матрицу Выбора из `other/distributor_screening/README.md`).
   - **ОБЯЗАТЕЛЬНО сохраняй оба отчета в файлы**: 
     - Сохрани сырой аналитический отчет, полученный от NotebookLM (или Perplexity), в файл `other/distributor_screening/<название_бренда>/notebooklm_report.md`.
     - Сохрани свои собственные выводы (Финальный сводный отчет после валидации с БД) в файл `other/distributor_screening/<название_бренда>/final_analysis.md`.

## Ограничения
- Искать только B2B контакты (не розничные магазины).
- Приоритет — дистрибьюторы в Евросоюзе.
