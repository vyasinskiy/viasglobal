# Инструкция для ИИ (verify-private-label)

## Триггеры активации
Этот навык активируется, когда пользователь произносит:
- "проверь приватный лейбл [бренд] [продавец]"
- "проверь связку [бренд] [продавец]"
- "является ли связка [бренд] + [продавец] приватным лейблом?"
- "это приватный лейбл?"

## Задача
Проверить гипотезу о том, что конкретный продавец торгует определенным брендом по модели Private Label, используя данные в базе данных PostgreSQL.

## Бизнес-процесс проверки
1. **Сбор параметров**:
   - Название бренда (`brandName`) или его ID.
   - Имя продавца (`sellerName`) или его `sellerId`.
   - Если пользователь не указал их, запросить по очереди: сначала бренд, затем продавца.

2. **Предварительная проверка загрузок (KeepaExport)**:
   - Для достоверного анализа доминирования в базе **ОБЯЗАТЕЛЬНО требуются 2 выгрузки Keepa**:
     1. **Выгрузка по бренду** (каталог бренда, `KeepaExport` с `brandId`).
     2. **Выгрузка по продавцу** (витрина продавца, `KeepaExport` с `sellerId`).
   - **Доклад и запрос разрешения на загрузку**:
     - Если отсутствует хотя бы одна выгрузка (по бренду или по продавцу), ИИ **ОБЯЗАН немедленно доложить пользователю**, какой именно выгрузки не хватает (указать точное название бренда и/или имя и Seller ID продавца).
     - ИИ **НЕ делает поспешных выводов** без полных выгрузок.
     - ИИ **запрашивает у пользователя разрешение** запустить автоматическую выгрузку с помощью специализированных навыков:
       - Для каталога бренда: навык `keepa-brand-finder-playwright` (`cd backend && npx tsx ../.agents/skills/keepa-brand-finder-playwright/scripts/fetch-brand-finder.ts "<brandName>"`).
       - Для витрины продавца: навык `keepa-seller-finder-playwright` (`cd backend && npx tsx ../.agents/skills/keepa-seller-finder-playwright/scripts/fetch-seller-finder.ts "<sellerId>"`).
     - **Важное правило при 0 товаров в выгрузке Playwright**:
       - Если после работы скрипта `keepa-brand-finder-playwright` вернулось 0 товаров, **НЕЛЬЗЯ делать вывод, что у бренда нет товаров или листинги удалены**.
       - Название бренда берётся напрямую из проверенной выгрузки Keepa, поэтому бренд гарантированно существует в Keepa.
       - Результат «0 товаров» указывает на то, что **Playwright допустил ошибку** при взаимодействии с формой (например, кликнул вариант `(no match)` в автодополнении, не дождался подгрузки списка подсказок или очистил инпут).
       - В этом случае ИИ **обязан прямо сообщить пользователю о сбое Playwright при выборе бренда** и предложить перепроверить селектор/автодополнение либо сделать выгрузку вручную по прямой ссылке [Keepa Product Finder](https://keepa.com/#!finder).
     - Если автоматическая выгрузка через браузер недоступна или пользователь предпочитает ручную выгрузку: предоставить пользователю прямую ссылку на [Keepa Product Finder](https://keepa.com/#!finder), сообщить фильтр и Seller ID / Brand Name, и дождаться загрузки файла через `cd backend && npx tsx scripts/parse-keepa.ts <путь_к_выгрузке.xlsx>`.
   - Запуск скрипта проверки через `run_command` (из директории `backend`):
     ```bash
     cd backend && npx tsx scripts/verify-private-label.ts "<brandName>" "<sellerId_or_sellerName>"
     ```
   
3. **Запрос детальной информации о продавце с Amazon**:
   - Попросить пользователя прислать скриншот или скопировать текст из блока **"Детальная информация о продавце"** (*Detailed Seller Information* / *Información detallada sobre el vendedor*) со страницы продавца на Amazon:
     - Юридическое наименование компании (*Nombre de empresa*).
     - Страна и адрес регистрации (*Dirección empresarial*).
     - Номер в торговом реестре (*Número de registro mercantil*).
     - Номер плательщика НДС (*Número de IVA / VAT*).
     - Контакты (телефон, email службы поддержки).
   - **Анализ юридического лица**:
     - Сопоставить страну, адрес, телефон и email продавца с брендом/производителем.
     - Проверить совпадение терминов/смысла названий (например, нидерландское *De Halve Garen BV* (пряжа) $\leftrightarrow$ испанское *Hilos y Sueños* (нитки/пряжа) $\leftrightarrow$ бренд пряжи *Scheepjes*).
     - Проверить природу номера IVA (например, `ESN...` - иностранная компания-нерезидент в Испании под FBA).

4. **Анализ результатов и метрик в БД**:
   - **Автоматическое совпадение**: Если связка уже зафиксирована в таблице `PrivateLabel` или имя продавца содержит бренд (`BUYBOX_MATCH_BRAND`), связка подтверждается сразу.
   - **Анализ каталога и витрины в БД**:
     - Скрипт проверяет критерии:
       1. Доля товаров с 1 продавцом (`newOfferCountCurrent = 1`) > 50%.
       2. Доля удержания BuyBox целевым продавцом на товарах бренда > 90% (или доминирование в каталоге >= 80% через `check_brand_seller_dominance`).
     - Если хотя бы одно условие выполнено $\Rightarrow$ **Private Label / Доминантный монополист подтвержден**.
     - Иначе $\Rightarrow$ **Подтвержден Wholesale (открытый оптовый рынок)**.

5. **Дальнейшие действия (Ветвление)**:
   - **Если вердикт: Private Label**:
     - Сформировать заметки анализа (`notes`), содержащие **только ключевые юридические и аналитические доказательства связей и выводы** (совпадение страны регистрации юрлица с брендом, номер NIF/IVA нерезидента под FBA, прямая связь вендора/email с брендом, семантическое сходство названий, процент удержания Buy Box), **без сырых административных данных вроде адреса и телефона**.
     - Если записи еще нет в `PrivateLabel`, спроси пользователя:
       > *"Связка подтверждена как Private Label. Добавить её в базу данных (в таблицу PrivateLabel с сохранением результатов анализа в поле notes)?"*
     - При согласии активируй навык `add-private-label` и передай сформированные заметки в `ANALYSIS_NOTES`.
   - **Если вердикт: Wholesale (не Private Label)**:
     - Сообщи, что бренд перспективен для оптовых закупок и на его листингах здоровая конкуренция.
     - Спроси пользователя:
       > *"Бренд подходит для оптовых продаж (Wholesale). Найти официальных B2B дистрибьюторов в Европе для бренда `<brandName>`?"*
     - При согласии активируй навык `find-distributor`.
