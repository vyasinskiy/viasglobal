# Инструкция для ИИ (verify-private-label)

## Триггеры активации
Этот навык активируется, когда пользователь произносит:
- "проверь приватный лейбл [бренд] [продавец]"
- "проверь связку [бренд] [продавец]"
- "является ли связка [бренд] + [продавец] приватным лейблом?"
- "это приватный лейбл?"

## Задача
Проверить гипотезу о том, что конкретный продавец торгует определенным брендом по модели Private Label, используя данные в базе данных PostgreSQL.

## Бизнес-процесс проверки
1. **Сбор параметров**:
   - Название бренда (`brandName`) или его ID.
   - Имя продавца (`sellerName`) или его `sellerId`.
   - Если пользователь не указал их, запросить по очереди: сначала бренд, затем продавца.

2. **Запуск скрипта проверки**:
   - Выполни команду запуска скрипта проверки через `run_command` (из директории `backend`):
     ```bash
     cd backend && npx tsx scripts/verify-private-label.ts "<brandName>" "<sellerId_or_sellerName>"
     ```
   
3. **Анализ результатов**:
   - **Автоматическое совпадение**: Если связка уже есть в таблице `PrivateLabel` или имя продавца содержит бренд (`BUYBOX_MATCH_BRAND`), связка подтверждается сразу.
   - **Анализ листингов в БД**:
     - Если товаров бренда в БД нет, сообщить пользователю и предложить сначала распарсить выгрузку продавца через навык `parse-keepa`.
     - Если товары есть, скрипт проверит критерии:
       1. Доля товаров с 1 продавцом (`newOfferCountCurrent = 1`) > 50%.
       2. Доля побед целевого продавца в BuyBox > 90%.
     - Если хотя бы одно условие выполнено $\Rightarrow$ **Private Label подтвержден**.
   - **Анализ цен и недоминантных продавцов**:
     - Сравнивать текущую цену товара со **средней ценой этого же товара за 90 дней (`buyBox90DaysAvg`)** и рекомендованной ценой (`listPriceCurrent`).
     - Не делать ложных выводов о завышении цен при сравнении с разнородным каталогом.
     - Делать взвешенный вывод для Wholesale: сторонним продавцам эти единичные позиции могут быть выгодны в рамках их штучной модели, но для нашей оптовой стратегии бренд **не подходит**, так как 90–99% каталога монополизировано, а открытой дистрибуции нет.

4. **Дальнейшие действия**:
   - Если связка **подтверждена** как Private Label (и ее еще нет в таблице `PrivateLabel`), спроси пользователя:
     > *"Связка подтверждена как Private Label. Добавить её в базу данных (в таблицу PrivateLabel)?"*
   - При согласии пользователя активируй навык `add-private-label` для создания скрипта миграции данных.
