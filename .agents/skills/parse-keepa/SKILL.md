# Инструкция для ИИ

## Триггер активации
Этот навык активируется, когда пользователь произносит фразы вроде "распарси выгрузку [путь_к_файлу]" или "проверь выгрузку [путь_к_файлу]".

## Задача
Пользователь передает файл выгрузки Keepa (в формате Excel). Твоя задача — запустить скрипт, который:
1. Проверит все ASIN-ы в файле. Если каких-то ASIN-ов нет в нашей базе данных, скрипт их создаст.
2. Все вновь добавленные ASIN автоматически добавляются в очередь запросов Keepa (`RequestProductQueue`) с высоким приоритетом (50) для последующего сбора карточек товаров и расчета метрик.
3. Проверит колонку производителя (Manufacturer). Новых производителей, которых нет в БД, добавит.
4. Проверит колонку брендов (Brand). Новых брендов, которых нет в БД, добавит.

## Алгоритм работы
1. **Запуск скрипта парсинга**:
   - Выполни следующую команду, находясь в директории `backend` (это важно для доступа к клиенту Prisma).
   - Скрипт автоматически определит, является ли выгрузка "общей" или принадлежит конкретному продавцу, проанализировав колонку Buy Box.
     ```bash
     cd backend && npx tsx scripts/parse-keepa.ts <путь_к_исходному_файлу_от_корня>
     ```
   - Пример использования:
     ```bash
     cd backend && npx tsx scripts/parse-keepa.ts ../keepa/exports/file.xlsx
     ```

2. **Результат**:
   - Сообщи пользователю результаты выполнения скрипта (сколько добавлено новых ASIN-ов, брендов, производителей), основываясь на выводе в консоли.

## Сплошная выгрузка прайс-листов дистрибьюторов через Keepa Viewer

- При обработке любых прайс-листов дистрибьюторов **все 100% EAN из прайс-листа** обязательно предварительно прогоняются через Keepa Product Viewer (навык `fetch-keepa-viewer`) для получения актуальных данных со стороны Amazon.
- Скачанный Excel-файл обязательно импортируется через `parse-keepa.ts`. Это создает свежие снапшоты в таблице `ProductFinder` с реальными ценами Buy Box, комиссиями FBA, габаритами и весом, а также обеспечивает заполнение связок `ASIN <-> EAN` в базе данных.
