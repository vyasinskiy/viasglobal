# Навык: Google Calendar (Управление календарем и дедлайнами)

Этот навык обеспечивает прямое взаимодействие с учетной записью **Google Calendar** через Google Calendar API (сервисный аккаунт / Service Account).
Он исключает зависимость от конкретных локальных почтовых или календарных клиентов на компьютере (macOS Calendar, Outlook и т.д.) и синхронизирует события напрямую в облако Google.

## 📝 Стандарт оформления событий

### 1. Заголовок (Summary)
Формат: `[Префикс]: Суть события`
- Примеры:
  - `[Legal]: Envases RAP — Проверить сертификат Procircular и подать в RPP (MITERD)`
  - `[Legal]: Сдать Modelo 303 по НДС за 3 квартал`
  - `[E-commerce]: Созвон с менеджером Alfa Dyser по условиям MOQ`
  - `[E-commerce]: Отгрузка партии товаров на склад Amazon FBA MAD4`

### 2. Описание (Description)
Описание обязательно структурируется по блокам:
```markdown
📌 Контекст:
Краткое описание предыстории и цели (почему и зачем это делается).

✅ Чек-лист действий:
1. Конкретный шаг 1
2. Конкретный шаг 2
3. Конкретный шаг 3

📂 Связанные файлы:
- Путь к файлу инструкции или договора в репозитории

🔗 Порталы и ссылки:
- Ссылка на официальный государственный или партнерский сервис
```

### 3. Напоминания (Reminders)
- Для дедлайнов и задач: всплывающие уведомления за 24 часа (1440 мин), 2 часа (120 мин) и 30 минут.
- Для встреч и созвонов: уведомления за 30 минут и 10 минут.

## 🛑 Правило «Анти-слепые изменения» (Обязательное согласование)

> [!CAUTION]
> **ИИ КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО самостоятельно создавать, вычеркивать (завершать) или удалять события и задачи в Google Calendar / Google Tasks без предварительного согласования с пользователем!**

### 1. Правило согласования вычеркивания и удаления:
Прежде чем что-либо вычеркивать (`task:complete`), удалять (`task:delete` / `delete`) или изменять в **Google Tasks** или **Google Calendar**, ИИ **обязан запросить явное разрешение пользователя**.
Запрос должен обязательно содержать:
1. **Точное описание сущности**: Заголовок, дата/дедлайн, категория и идентификатор (ID).
2. **Обоснование («Почему»)**: Подробное объяснение причины, почему задачу или событие предлагается вычеркнуть или удалить (например: *«регистрация пройдена, получен официальный номер ENV/2026/...»*).
3. **Ожидание ответа**: Выполнять действие разрешено ТОЛЬКО после прямого подтверждения пользователя («Да», «Вычеркивай», «Удаляй»).

### 2. Категорическое разграничение задач (Google Tasks) и событий (Google Calendar):
- 📌 **Google Tasks (`task:create`)**: ВСЕ дедлайны, проверки, верификации (Follow-up Tasks), поручения, напоминания и чек-листы создаются **СТРОГО И ИСКЛЮЧИТЕЛЬНО как задачи в Google Tasks**.
  > **Причина**: События в календаре (`calendar:create`) нельзя отметить как выполненные (нет чекбокса/галочки). Задачи в Google Tasks автоматически выводятся вверху соответствующего дня в интерфейсе Google Календаря с кружком-чекбоксом (`O`), не захламляют временные интервалы дня и вычеркиваются в один клик.
- 📅 **Google Calendar (`calendar:create`)**: События в сетке календаря разрешено создавать **ТОЛЬКО для реальных созвонов, встреч и переговоров с людьми** (с внешними участниками, поставщиками, нотариусом), где есть четко зафиксированное время начала и конца.

### 3. Правило обязательного создания дедлайнов в Google Tasks:
> **Каждый обнаруженный или появившийся дедлайн (регуляторный, юридический, налоговый, коммерческий) ИИ ОБЯЗАН автоматически оформлять в виде задачи в Google Tasks (а НЕ события в календаре).**
Не допускается оставлять дедлайны только в тексте переписки — они должны быть овеществлены в системе контроля сроков с датой выполнения (`--due`) и пошаговым чек-листом.

### 4. Правило контроля ожиданий, проверок и верификаций (Follow-up Tasks в Google Tasks):
> **Если мы чего-либо ждем (результата верификации документов, проверки регистрационного номера маркетплейсом/регулятором, ответа поставщика, решения модерации), ИИ ОБЯЗАН автоматически создать задачу в Google Tasks (а НЕ событие в календаре!) на крайнюю дату (дедлайн) этого ожидания.**
Цель задачи: проверить статус, убедиться в успешном прохождении проверки или оперативно отреагировать при возникновении замечаний/отказа.
*Пример*: если отправлен номер RAP на валидацию в Amazon или в Procircular с регламентом до 24-48 часов (с учетом рабочих дней), ровно на эту дату создается задача в Google Tasks для проверки результата.

### 5. Обязательное линкование задач в документации проекта:
> **Любая задача в Google Tasks, созданная для контроля дедлайна, проверки или предстоящего действия, ОБЯЗАНА напрямую линковаться в документации проекта (`README.md` соответствующего раздела).**
В блоке предстоящих действий (Roadmap / To-Do) документации обязательно указывается: заголовок задачи, дедлайн, ее идентификатор (`ID`) и прямая кликабельная ссылка `webViewLink` из ответа Google Tasks API (`https://tasks.google.com/task/<decoded_id>?sa=6`, выводимая скриптом `calendar.ts`). **Внимание:** категорически запрещено подставлять сырой Base64 `task.id` напрямую в URL (`https://tasks.google.com/task/<base64_id>`), так как веб-интерфейс Google Tasks использует декодированный идентификатор из поля `webViewLink`! Запрещено оставлять предстоящие действия только текстом в документации без привязанной активной задачи.

### 6. Обязательное бизнес-правило по счетам-фактурам (Factura) и налоговому сервису Taxfix (`[Legal]`):
> **Каждый раз, когда пользователь получает или присылает счет-фактуру (`Factura` / `INVOICE`), она должна быть загружена в налоговый сервис Taxfix, к ней должен быть прикреплен факт оплаты из банка (`PAYMENT_RECEIPT`), и оба документа должны быть слинкованы между собой в Taxfix.**
На каждую поступившую фактуру обязательно формируется задача в **Google Tasks** с категорией **`[Legal]`**:
- **Заголовок**: `[Legal]: Taxfix — Загрузить фактуру <Номер> (<Поставщик>) и слинковать с банковской оплатой`
- **Чек-лист в описании**:
  1. Проверить корректность реквизитов (`Vitalii Iasinskii`, NIF `ESZ1154366R`, адрес `Ronda Albocacer 11, 12166 Els Ibarsos`) и загрузить PDF фактуры в сервис **Taxfix**.
  2. Выгрузить из банка подтверждение оплаты (`PAYMENT_RECEIPT` — выписка по карте, переводу или SEPA Direct Debit) и прикрепить к заказу/фактуре (в репозитории и через `POST /orders/:id/taxfix`).
  3. Слинковать загруженную фактуру с банковской транзакцией оплаты в сервисе **Taxfix** и отметить статус сверки (`uploadedToTaxfix: true`, `paymentLinkedInTaxfix: true`).

### 7. Карточка согласования перед созданием:
Перед созданием новой задачи в Google Tasks или события в Календаре ИИ формирует наглядную карточку:
- 📅 **Дата дедлайна / время**: (например, `дедлайн: 2026-10-27`)
- 🏷️ **Категория**: `[Legal]` / `[E-commerce]` / `[Tech]`
- 📝 **Заголовок**: `[Категория]: Название задачи`
- 📋 **Описание**: контекст, пошаговый чек-лист действий, ссылки
- 👤 **Инструмент / Список**: `Google Tasks (список Tasks)`

## 💻 Исполняемые команды
Скрипт утилиты: [calendar.ts](./scripts/calendar.ts)

### А. Работа с задачами (Google Tasks):
> **Правило**: Все задачи сохраняются **строго в единый общий список `Tasks`** пользователя, без создания отдельных списков. Категория определяется префиксом заголовка (`[Legal]: ...` или `[E-commerce]: ...`).
1. **Просмотр списка открытых задач**:
   ```bash
   npx tsx .agents/skills/google-calendar/scripts/calendar.ts task:list
   ```
2. **Создание задачи (автоматически попадает в общий список `Tasks`)**:
   ```bash
   npx tsx .agents/skills/google-calendar/scripts/calendar.ts task:create \
     --category "Legal" \
     --title "Envases RAP — Проверить сертификат Procircular и подать в RPP" \
     --due "2026-10-26" \
     --notes "📌 Контекст: Получен сертификат...\n✅ Чек-лист:..."
   ```
3. **Отметка задачи выполненной (вычеркнуть)**:
   ```bash
   npx tsx .agents/skills/google-calendar/scripts/calendar.ts task:complete --id "<TASK_ID>" --category "Legal"
   ```
4. **Обновление задачи (заголовок, описание, дедлайн)**:
   ```bash
   npx tsx .agents/skills/google-calendar/scripts/calendar.ts task:update \
     --id "<TASK_ID>" \
     --title "Новый заголовок" \
     --notes "Новое описание с чек-листом" \
     --due "2026-10-28" \
     --category "Legal"
   ```
5. **Удаление задачи**:
   ```bash
   npx tsx .agents/skills/google-calendar/scripts/calendar.ts task:delete --id "<TASK_ID>" --category "Legal"
   ```


### Б. Работа с событиями в сетке календаря (Google Calendar):
1. **Просмотр событий**:
   ```bash
   npx tsx .agents/skills/google-calendar/scripts/calendar.ts list --days 14
   ```
2. **Создание события**:
   ```bash
   npx tsx .agents/skills/google-calendar/scripts/calendar.ts create \
     --category "Legal" \
     --title "Envases RAP — Проверить сертификат Procircular и подать в RPP" \
     --start "2026-10-26T10:00:00" \
     --end "2026-10-26T11:00:00" \
     --desc "..."
   ```
3. **Обновление события**:
   ```bash
   npx tsx .agents/skills/google-calendar/scripts/calendar.ts update \
     --id "<EVENT_ID>" \
     --category "Legal" \
     --title "Новое название"
   ```
