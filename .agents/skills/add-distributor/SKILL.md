# Инструкция для ИИ (Add Distributor)

## Триггер активации
Этот навык активируется, когда пользователь произносит фразу:
- **"добавь дистрибьютора"**
- **"свяжи дистрибьютора"**
- **"привяжи дистрибьютора к товарам / EAN / ASIN"**
- или аналогичную по смыслу фразу для добавления дистрибьютора в БД.

---

## Входные данные и пошаговый опрос

Для создания миграции необходимы:
1. **Наименование дистрибьютора** (`distributorName`).
2. **Сайт дистрибьютора** (`distributorWebsite`, опционально).
3. **Список товаров** (EAN или ASIN).

### Алгоритм опроса:
- Если не указано наименование дистрибьютора, спроси: *«Укажите название дистрибьютора:»*
- Если не указаны товары (EAN / ASIN), спроси: *«Укажите список EAN или ASIN для привязки к дистрибьютору:»*

---

## Требования к генерации скрипта миграции данных

1. **Подключение к БД**:
   Скрипт использует `pg` адаптер Prisma:
   ```typescript
   import { PrismaClient } from '@prisma/client';
   import { Pool } from 'pg';
   import { PrismaPg } from '@prisma/adapter-pg';

   const connectionString =
     process.env.DATABASE_URL ||
     'postgresql://viasuser:viaspassword@100.92.50.18:5432/viasglobal_db?schema=public';

   const pool = new Pool({ connectionString });
   const adapter = new PrismaPg(pool);
   const prisma = new PrismaClient({ adapter });
   ```

2. **Обязательная предварительная выгрузка всех EAN (Keepa Product Viewer)**:
   - Перед связыванием дистрибьютора с товарами **все 100% EAN из прайс-листа дистрибьютора** должны быть выгружены через Keepa Product Viewer (`fetch-viewer.ts`) и импортированы в БД (`parse-keepa.ts`).
   - Это гарантирует, что в таблице `ProductFinder` будут свежие актуальные снапшоты цен и параметров по всем позициям прайс-листа (включая товары без BSR).
   - Поиск EAN для привязки выполняется **напрямую через таблицу `ProductFinder`** (связь с `ASIN.productFinders` по полю `productCodesEAN`), без обращения к представлениям.

3. **КРИТИЧЕСКОЕ ТРЕБОВАНИЕ: Строгая валидация количества (100% совпадение)**:

   - В скрипте **обязательна проверка**: количество найденных в БД товаров должно строго равняться количеству переданных EAN/ASIN (`foundAsins.length === targetItems.length`).
   - Если хотя бы один товар/EAN не найден в базе данных, скрипт **обязан выбросить ошибку (`throw new Error`)** со списком всех ненайденных позиций и прервать выполнение.
   - **Недопустимо** сохранять дистрибьютора с неполным списком привязанных товаров.

4. **Сохранение дистрибьютора**:
   - Выполняется `prisma.distributor.upsert` с привязкой (`asins: { connect: [...] }`).

5. **Расположение и имя файла**:
   - Путь: `backend/prisma/data-migrations/add-<distributor-name>-distributor-<YYYYMMDDHHMMSS>.ts`.
   - Комментарии в коде скрипта пишутся подробно на русском языке над каждой строкой/блоком.

6. **Процесс согласования с пользователем**:
   - Скрипт создается через `write_to_file`.
   - Пользователю предоставляется ссылка на файл и вопрос: *«Выполнить этот скрипт миграции сейчас?»*.
   - **НИКОГДА не запускать скрипт без явного подтверждения пользователя!**
   - После согласия пользователя запуск выполняется командой:
     `npx tsx prisma/data-migrations/<файл>.ts` (в директории `backend/`).
