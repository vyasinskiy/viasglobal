# Навык: Distributor Emails (Почта и переписка с поставщиками)

Этот навык предназначен для работы с электронной почтой поставщиков и дистрибьюторов через почтовый ящик Hostinger.
Он позволяет:
1. Загружать новые письма по протоколу IMAP и сохранять их в локальную базу данных (`DistributorEmail`).
2. Автоматически сопоставлять отправителей с дистрибьюторами (`Distributor`), находить персональных менеджеров и сохранять контакты (`DistributorContact`).
3. Быстро находить коммерческие условия (порог бесплатной доставки *franco de portes*, минимальный заказ *MOQ/MOV*, скидки, каталоги) прямо в локальной БД без повторных сетевых запросов.
4. Автоматически сохранять прикрепленные прайс-листы и каталоги (`.xlsx`, `.pdf`) в папку поставщика `contractors/<дистрибьютор>/attachments/`.

## 🛑 Категорический запрет на отправку писем (Только чтение / Read-Only)

> [!CAUTION]
> **ИИ КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО ОТПРАВЛЯТЬ ЛЮБЫЕ ЭЛЕКТРОННЫЕ ПИСЬМА!**
> 
> Почтовая подсистема работает **СТРОГО В РЕЖИМЕ ЧТЕНИЯ (Read-Only через IMAP)**:
> 1. **Никаких исходящих сообщений**: ИИ категорически запрещено инициировать отправку писем (через SMTP, скрипты, почтовые API или любые другие инструменты). В проекте намеренно отсутствует функционал отправки писем от имени ИИ.
> 2. **Только аналитика и поиск**: ИИ разрешено исключительно подключаться к почтовому ящику по протоколу IMAP, скачивать входящую/исходящую корреспонденцию в локальную базу данных, искать условия поставщиков (порог бесплатной доставки, минимальный заказ) и скачивать вложенные файлы (прайс-листы, каталоги).
> 3. **Черновики только пользователю**: Если пользователю требуется ответ поставщику, ИИ формирует текст ответа **исключительно в чате в виде проекта письма** для ручной проверки и самостоятельной отправки пользователем.

## 📋 Пошаговый алгоритм для ИИ

### Шаг 1. Проверка наличия и актуальности переписки

Если пользователь спрашивает о недавнем письме или просит проверить условия:
1. Выполни синхронизацию входящих писем из почтового ящика в БД:
   ```bash
   cd ecommerce/backend && npx tsx scripts/sync-emails.ts --limit 30
   ```
2. Скрипт:
   - Подключается к IMAP серверу Hostinger (`imap.hostinger.com:993`).
   - Скачивает свежие письма.
   - Автоматически находит дистрибьютора по email, домену сайта или контакту менеджера.
   - Если менеджер (например, Guido) еще не заведен в базе, автоматически добавляет его в `DistributorContact`.
   - Если в письме есть прайс-лист Excel или PDF, скачивает его в папку `contractors/<дистрибьютор>/attachments/`.

> [!NOTE]
> Если учетные данные `IMAP_USER` или `IMAP_PASSWORD` еще не указаны в `ecommerce/backend/.env`, скрипт сообщит об этом. В таком случае вежливо попроси пользователя прописать их в файле `ecommerce/backend/.env`.

---

### Шаг 2. Поиск условий в локальной базе данных писем

Для мгновенного поиска по тексту переписки используй скрипт:
```bash
cd ecommerce/backend && npx tsx scripts/search-distributor-emails.ts --distributor "<ИмяДистрибьютора>" --query "<КлючевоеСлово>"
```

**Примеры запросов:**
- Поиск условий доставки для Kuken:
  ```bash
  cd ecommerce/backend && npx tsx scripts/search-distributor-emails.ts --distributor "Kuken" --query "portes"
  ```
- Поиск минимального заказа:
  ```bash
  cd ecommerce/backend && npx tsx scripts/search-distributor-emails.ts --distributor "Alfadyser" --query "mínimo"
  ```
- Поиск всех писем конкретного контрагента:
  ```bash
  cd ecommerce/backend && npx tsx scripts/search-distributor-emails.ts --distributor "Kuken"
  ```

### Шаг 3. Анализ и ответ пользователю

1. Внимательно изучи найденные фрагменты переписки:
   - Кто отправитель (имя менеджера, должность).
   - Дата и время отправки письма.
   - Точные числовые значения: порог бесплатной доставки (*portes pagados* / *franco* в евро), сумма минимального заказа, стоимость платной доставки.
   - Ссылка на вложенные файлы, если поставщик прислал новый файл прайс-листа.
2. Сформируй четкий структурированный ответ пользователю:
   - Приведи точную цитату фрагмента письма на испанском языке.
   - Дай перевод и вывод на русском языке.
   - Укажи дату письма и контакт менеджера.

### Шаг 4. Переход к онбордингу и отправка документов (Ficha de Cliente / Alta / SEPA / Первый заказ)

> [!IMPORTANT]
> **Разделение этапов**: Первичное приветственное письмо (*Welcome Letter*) служит только для запроса прайса и условий. Но когда поставщик согласовал сотрудничество и переходит к **открытию карточки клиента (Ficha de cliente / Alta de cliente / Mandato SEPA / первый заказ)**, начинается передача юридических документов и реквизитов, на основе которых формируются фактуры для Amazon.

#### ⚠️ Критическая ошибка европейских менеджеров при регистрации (Фамилия IASINSKII vs LASINSKII)
- **Суть проблемы**: В гротескных шрифтах без засечек заглавная английская буква **`I`** неотличима от строчной **`l`**. Менеджеры и операторы поставщиков систематически путают первую букву и заводят карточку клиента на имя **`LASINSKII`** вместо **`IASINSKII`**.
- **Последствия**: В счетах-фактурах (*Factura*) это приводит к ошибке **Name Mismatch** при проверке в Amazon Seller Central, из-за чего заявка на Brand Ungating / Category Approval гарантированно отклоняется.
- **Обязательное правило при подготовке любых ответов и форм онбординга**:
  Включать явное примечание с расшифровкой первой буквы фамилии и эталонные реквизиты из [`other/company_profile.md`](file:///Users/usuario/code/viasglobal/other/company_profile.md):
  ```markdown
  Datos para la ficha de cliente y facturación:
  - Razón Social / Nombre: Vitalii Iasinskii
    *Nota: El apellido comienza por la letra "I" mayúscula (I de Iglesia), no por "L".
  - NIF: Z1154366R
  - Dirección fiscal y de entrega: Ronda Albocacer 11, 12166 Ibarsos (Castellón), España
  - Teléfono: +34 641 064 851
  - Email de facturación: info@viasglobal.es
  ```
- **Проверка первого Albarán / Factura**: При получении первой накладной (Albarán) или фактуры ИИ обязан немедленно сверить ФИО (`IASINSKII`), адрес (`12166 Ibarsos`) и NIF (`Z1154366R`). Если обнаружена ошибка, сразу сформировать вежливое письмо поставщику с просьбой исправить карточку в ERP до выставления закрывающих документов.
