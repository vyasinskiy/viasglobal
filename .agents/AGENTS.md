# Требования к проекту (Viasglobal)

- **Язык**: Все комментарии в коде и документация (README) должны быть на **русском языке**.
- **Стек**: Next.js (App Router), Vanilla CSS + Material-UI (MUI).
- **Дизайн**: 
  - Использовать цвета, близкие к Amazon (оранжевый, черный, белый, темно-синий/серый), для обеспечения консистентности.
  - Дизайн должен быть современным (с использованием CSS variables).
- **GDPR compliance (Евросоюз/Испания)**: 
  - Наличие баннера согласия на использование Cookie.
  - Страницы Политики конфиденциальности, Условий использования (Aviso Legal) и Политики файлов cookie.
- **Контакты**: Вместо формы обратной связи использовать простую кнопку `mailto:` с адресом `info@viasglobal.es`. Все контактные данные (имейл, домен viasglobal.es, название компании) выносить в переменные/константы, чтобы их было легко менять.
- **Хостинг**: Деплой на Vercel (стандартный билд, $0/мес).

## Правила документирования

- **Запись ответов на вопросы**: Любые важные ответы на вопросы или решения проблем, касающиеся конкретной части проекта (например, лендинга, почтовой подписи, парсера Keepa), должны обязательно записываться в локальный агентский файл (например, `landing/AGENTS.md`) соответствующей директории. Я не должен просто отдавать ответ в чате, я обязан сохранить это знание в код.
- **Двойная документация**: Когда пользователь уточняет какие-либо ссылки (например, на дашборды), описание проекта, бизнес-логику или требования, я обязан поддерживать в актуальном состоянии **ОБА** файла: `README.md` (для человека, подробное описание и ссылки) и `AGENTS.md` (для ИИ, короткие правила и ссылки на README).
- **Чтение документации**: Если пользователю нужна помощь с настройкой, хостингом, бизнес-логикой, поиском дашбордов или деталями проекта, **обязательно** сначала прочитай соответствующий файл `README.md` (например, `landing/README.md`). Там находится вся подробная информация для человека, и мои ответы должны давать точные ссылки и инструкции на ее основе.
